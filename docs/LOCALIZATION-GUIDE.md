# 多语言翻译规范（Localization Guide）

本规范用于保证英文翻译的准确性、一致性和可验证性，避免 AI 翻译丢信息、跑题、风格漂移。

## 1. 目标

1. 不丢信息：原文中的事实、限定词、语气、关系必须完整保留。
2. 不改结构：只翻译 value，不改 key，不改数组顺序，不改数据类型。
3. 一致可复用：同一术语在全项目统一翻译。
4. 可验收：每一批翻译都能通过结构校验和语义抽检。

## 2. 翻译范围优先级

1. UI 静态文案（按钮、标题、提示语）。
2. 问卷题干和选项（questions）。
3. 结果页文案和说明。
4. 人格故事与长文本（story templates）。

## 3. 硬性约束（必须遵守）

1. 不翻译 key：JSON key、代码常量、类型名保持原样。
2. 不改标识符：如 W1-W4、I1-I4、组合键 W1_I1 等不可改动。
3. 不改占位符：如变量插值、日期格式占位、字符串拼接符号必须保留。
4. 不增删字段：源语言和目标语言对象结构必须完全同构。
5. 不改业务语义：不能把“建议/可能”翻成“必须/确定”。

## 4. 术语表（锁定翻译）

1. 孙承完 -> Shon Seung-wan
2. 裴柱现 -> Bae Ju-hyeon
3. 人格测试 -> personality test
4. 测试结果 -> test result
5. 更新日志 -> changelog
6. 更新历史 -> history
7. 开始测试 -> Start Quiz
8. 查看结果 -> View Result
9. 测试说明 -> How it works
10. 本测试仅供娱乐，所有人格特质均为虚构设定 -> This test is for entertainment only. All personality settings are fictional.

## 5. 风格准则

1. 语气：简洁、自然、偏产品文案，不用过于学术或机器化表达。
2. 人称：默认第二人称（you），保持一致。
3. 长度：按钮文案尽量短；移动端优先可读性。
4. 标点：英文使用英文标点，不混用中文标点。
5. 专有名词：按术语表执行，不自由改写。

## 6. 执行流程（每批次）

1. 冻结结构：先确定本批要翻译的 JSON 文件和 key 列表。
2. 术语预检：新增词汇先补到术语表再翻译。
3. 批量翻译：逐文件翻 value，保留结构。
4. 结构校验：对比 key 数、数组长度、字段顺序、占位符一致性。
5. 语义抽检：随机抽 20% 文案回译，检查信息等价。
6. 页面验收：在页面中检查换行、截断、按钮宽度和可读性。

## 7. 质量检查清单（发布前）

1. 英文文件可正常被页面加载。
2. 语言切换后无 undefined 文案。
3. 每个翻译文件与中文源文件结构一致。
4. 按钮、标签、标题在移动端不溢出。
5. 术语统一，无同词多译。
6. 人名拼写符合术语表。

## 8. 文件组织建议

1. 每个页面一对字典文件：zh-CN 和 en-US。
2. 命名保持一致，便于自动加载和 diff。
3. 与页面一一对应，避免超大字典文件。

推荐结构示例：

- src/i18n/dictionaries/home/zh-CN.json
- src/i18n/dictionaries/home/en-US.json
- src/i18n/dictionaries/quiz/zh-CN.json
- src/i18n/dictionaries/quiz/en-US.json
- src/i18n/dictionaries/result/zh-CN.json
- src/i18n/dictionaries/result/en-US.json

## 9. 变更记录规则

1. 每次术语调整要记录到本文件。
2. 修改已上线文案时，先评估是否影响截图、测试用例和埋点文案。
3. 高风险改动（题目和结果解释）建议分支审校后再合并。

## 10. 本项目当前约定

1. 首页文案已接入字典。
2. 当前支持语言：zh-CN、en-US。
3. 英文人名采用韩语罗马字：Shon Seung-wan、Bae Ju-hyeon。
